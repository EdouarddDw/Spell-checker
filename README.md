# Spell-checker

Local spelling correction for English and French. The end goal is a keyboard
shortcut that sends the selected text to a local LLM and shows a diff to accept
or reject.

This repo currently holds only the **evaluation harness**: it measures how well
a *prompted* (not fine-tuned) model corrects spelling, to get a baseline before
deciding whether to fine-tune a smaller model.

```
data/sentences_{en,fr,mixed}.txt   clean sentences, one per line (yours)
data/eval.jsonl                    generated by make_eval.py
prompts/v1.txt                     system prompt + few-shot examples
make_eval.py                       injects spelling errors into the sentences
baseline.py                        runs the model on eval.jsonl and scores it
results/<timestamp>_<label>/       one folder per run
tests/
```

## Setup

Python 3.11+. The two scripts use the standard library only; pytest is needed
for the tests.

```sh
uv run pytest            # with uv
# or
python3 -m venv .venv && .venv/bin/pip install pytest && .venv/bin/python -m pytest
```

## Start the server

Any OpenAI-compatible endpoint works. With llama.cpp:

```sh
llama-server -hf bartowski/Qwen_Qwen3.5-4B-GGUF:Q4_K_M --port 8080 --reasoning-budget 0
```

`--reasoning-budget 0` turns thinking off. With thinking on, `baseline.py`
still works (it strips `<think>` blocks and prints a warning), but every request
takes many times longer and the latency and tokens/sec numbers measure the
thinking, not the correction.

## 1. Build the eval set

```sh
python3 make_eval.py
```

Reads the three sentence files and writes `data/eval.jsonl`. If a sentence file
is missing, a placeholder with 20 sentences is created (first line starts with
`# PLACEHOLDER`; the script warns as long as that line is there). Blank lines
and lines starting with `#` are skipped.

| Flag | Default | |
|---|---|---|
| `--seed` | `42` | same seed, same sentences: same output |
| `--clean-ratio` | `0.3` | share of examples left untouched |
| `--layout` | `qwertz-ch` | keyboard for adjacent-key typos: `qwerty`, `azerty`, `qwertz-ch` |
| `--variants` | `1` | examples generated per sentence (different errors each time) |
| `--data-dir`, `--out` | `data/`, `data/eval.jsonl` | |

Each corrupted sentence gets 1 to 3 errors, one word each. Error types:

| Type | Languages | Example |
|---|---|---|
| `adjacent_key` | all | pour → pkur |
| `transposition` | all | the → teh |
| `deletion` | all | rain → rin |
| `doubled_letter` | all | than → thhan |
| `phonetic` | all | written as it sounds: would → wood, pharmacy → farmasy, quand → kan, maison → mèzon |
| `en_confusion` | en, mixed | their/there/they're, your/you're, its/it's, then/than, from/form, lose/loose |
| `accent_strip` | fr, mixed | oublié → oublie |
| `accent_swap` | fr, mixed | élève → éléve |
| `fr_homophone` | fr, mixed | a/à, et/est, ces/ses/c'est/s'est, son/sont, on/ont, ou/où, ce/se |
| `verb_ending` | fr | arriver → arrivez |
| `dropped_plural` | fr, mixed | francs → franc |

Only the letters of a word are corrupted: punctuation, capitalisation and the
number of words never change. Each output line:

```json
{"id": "fr-0005", "lang": "fr", "input": "...", "target": "...", "clean": false,
 "errors": [{"word_index": 4, "type": "dropped_plural", "original": "francs", "corrupted": "franc"}]}
```

Known limits: there is no part-of-speech tagging, so `verb_ending` and
`dropped_plural` sometimes hit a word that is not a verb or a plural (the result
is still a misspelling with one obvious correction). In mixed sentences,
`verb_ending` is off and `a`/`on`/`son` are never swapped, because the script
cannot tell which words are English.

`phonetic` rewrites one or two sounds of a word (at least 4 letters) with fixed
spelling rules, not a pronunciation dictionary, so it only approximates what a
writer who does not know the word would produce. The result is sometimes
another real word (would → wood, sont → son). Mixed sentences use only the few
rules that hold in both languages (ph → f, single for double consonant,
-tion → -sion, y → i).

## 2. Run the baseline

```sh
python3 baseline.py --label qwen3.5-4b-v1
python3 baseline.py --limit 10            # quick check
```

| Flag | Default |
|---|---|
| `--eval` | `data/eval.jsonl` |
| `--url` | `http://localhost:8080/v1/chat/completions` |
| `--prompt` | `prompts/v1.txt` |
| `--limit` | all examples (the file is shuffled, so the first N mix all languages) |
| `--label` | `baseline` |
| `--max-tokens`, `--timeout`, `--model`, `--results-dir` | `2048`, `300` s, none, `results/` |

Requests are sent one at a time at temperature 0. The run stops with an error
if the server cannot be reached.

To try another prompt, copy `prompts/v1.txt` to `prompts/v2.txt`, edit it, and
pass `--prompt prompts/v2.txt --label v2`. The format is a `### system` section
followed by `### user` / `### assistant` pairs.

## Reading the metrics

The output is aligned with the input word by word (`difflib`), and every
difference lands in one of four buckets:

- **fixed**: an injected error, corrected to the expected word.
- **missed**: an injected error left as is, or changed to something else.
- **false positive**: a word that was correct and got changed. Punctuation and
  capitalisation changes count.
- **rewrite**: a block where words were added, removed or re-split, so a
  one-to-one comparison is not possible. Counted per block.

The summary table has one row for the whole set, one per language, and one per
error type:

| Column | Meaning |
|---|---|
| `n` | examples in the row |
| `exact%` | output identical to the target |
| `recall%` | fixed / (fixed + missed) |
| `FP`, `FP/100w` | false positives, and per 100 input words. **The number to watch**: a corrector that changes correct text cannot be trusted |
| `clean ok%` | clean sentences returned exactly as they were |
| `rewr` | rewrite blocks |
| `lat mean`, `p50`, `p95` | seconds per request |
| `tok/s` | completion tokens / wall time, from the `usage` field |

In a `type:` row, the examples are those containing at least one error of that
type, and recall counts only errors of that type. The other columns cover the
whole example, which may also contain other error types.

Each run writes to `results/<timestamp>_<label>/`:

- `metrics.json`: everything in the table, plus the run settings.
- `outputs.jsonl`: one line per example with the model output and the
  fixed / missed / false-positive / rewrite details.
- `failures.jsonl`: the lines of `outputs.jsonl` where the output differs from
  the target. Start here when tuning the prompt.

## Before a real run

Replace the three files in `data/` with your own writing (a few hundred
sentences per language gives usable per-type numbers), then re-run
`make_eval.py`. The sentences must be correctly spelled: any mistake in them
becomes the "target" the model is scored against.
